## 1. 需求

### 1.1 一键售卖

- 商店背包框上方的空带里，在“批量出售”旁边加“一键售卖”。
- 不能点一下直接卖。流程必须是：**设置 → 预览 → 确认**。
- 设置项至少包括：装备等级上限、强化等级上限、品质上限、是否排除带宝石/带混沌的装备。
- 预览列表要能看出具体卖哪些装备；每件可以单独取消/恢复售卖。
- 点预览里的装备可以查看它的详情。
- 底部显示已选件数和预计收入，最后才是“确认售卖 / 取消”。
- 当前只针对**装备**；消耗品和材料继续走“批量出售”。

### 1.2 物品锁定

- 物品可以上锁/解锁；锁定后不能出售、丢弃（原版叫“粉碎”）、使用消耗品/技能书、作为合成/强化材料、把锁定宝石镶进装备。
- 锁定不影响装备、卸下、整理、移动格子、查看。
- 背包格和装备槽要有锁定样式。
- 物品说明面板要有“上锁/解锁”动作和锁定状态说明。

## 3. 筛选与数据设计

### 3.1 筛选条件

只处理背包里未穿戴的装备：

- 未锁定、可出售（`sellPrice > 0`）。
- `ItemDefinition.level ≤ 装备等级上限`。
- `ItemInstance.enhancement ≤ 强化等级上限`。
- 品质稀有度 `grades[entry.numbers?.grade ?? item.defaultGrade ?? 2].rarity ≤ 品质上限`。
- 勾选“不含带宝石装备”时 `entry.gems.length === 0`。
- 勾选“不含混沌装备”时 `!entry.numbers?.chaos`。

品质颜色沿用 `src/ui/item-name-color.ts`；稀有度 0–4 暂叫普通 / 优质 / 高级 / 黄装 / 紫装，后续可改文案。

建议把筛选做成 `domain` 纯函数，例如：

```text
bulkSellEquipment(entries, catalog, gradeTable, sellPrice, settings)
  → { entries: { entry, price }[], total }
```

预览和确认共用同一函数，避免预览与真正卖出不一致。

### 3.2 手动取消

- 预览列表维护一个“被排除的 entry id”集合；默认全部包含。
- 改筛选条件后重新计算候选，仍符合条件的排除项继续保持排除。
- 勾选框和详情里的“不卖这件/恢复售卖”是同一个状态。
- 确认时按当前勾选重新校验；任何一件在弹层打开后变了（上锁、被穿、数量变化），整批不卖并在弹层里显示原因。
- 成功后关闭弹层并提示“已卖出 N 件装备”。

## 4. 物品锁定的数据与界面

### 4.1 数据

- `ItemInstance.locked?: boolean`，整叠一起锁。
- 锁定物品不与未锁定同种物品合并（`holdsInstanceState` 要包含 `locked`）。
- 提升 `SAVE_FORMAT`（以实现时的当前值为准）；升级链补上一版到新版的迁移，旧档物品全部补 `locked = false`。
- `verifyBagState` 校验 `locked` 必须是布尔值。
- 需要拦住的背包方法：`discard`、`take`、`use`、`remove`（跳过锁定条目）、`swapGem`（锁定宝石不能作为来源）。
- `Storefront.sell` / `sellMany` 补明确的“物品已锁定，不能出售”错误。

### 4.2 背包样式草稿

- 背包格和装备槽右上角：18×18 深色底板 + 金色小锁（锁身、锁梁用基础矩形画；原版没有道具锁图标，不新增图片冒充原版素材）。
- 图标保持原色，不整格变灰；批量出售模式下降为 55% 透明度，小锁保持高亮。
- 物品说明：名称下加金色“已锁定”；底部动作增加“上锁/解锁”；锁定时隐藏“丢弃”，使用类动作置灰并说明原因。
- 上锁/解锁成功用 `showInstant` 提示。
