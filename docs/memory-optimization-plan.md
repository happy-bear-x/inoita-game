# 内存优化与技能缺图修复方案

已确定按实际学会的技能准备素材，并把调试标记持久化到设备。先修复已复现的技能缺图，再减少资源占用。每个独立问题完成修复和验证后单独提交。

## 技能缺图与战斗素材

1. 修复已复现的共享贴图丢失。黑暗骑士佣兵先学「黑暗的守护者」，主角随后学会同一招，佣兵离队后主角目前缺少 7 项贴图。每位使用者登记完整素材清单，下载只补缺项；换技能、装备和队员时先取得新清单的使用权，再释放旧清单。

2. 进图、学招、换装、入队和读档统一准备技能素材，覆盖手动施法、伙伴和敌人自动施法、被动追击及召唤物。新动作准备期间保留已有技能；准备失败可重试，新技能不扣蓝、不进入冷却。切图、离队和连续换装时，迟到的下载只能交给仍在等待的操作。

3. 飞弹持有飞行和转向所需图片，持续效果持有到结束，召唤物持有到退场。修复循环特效首次缺图后一直显示空画面的问题。文件或动画帧缺失时，诊断记录职业、技能、动作和文件，并核对原版素材。

4. 公共素材保留基础战斗反馈；按当前队伍、地图敌人及即将播放的剧情准备武器、技能、演员动作和剧情特效，覆盖分支、跳过和读档。以黑暗空间为样本，仅出场和对白的段落不加载约 19 MiB 的陨石动作图。像素和切帧相同的待机、攻击图共用图片，同时保留各自的播放速度和循环规则。

## 收回长期占用的内存

- 剧情播放器、进度校验器和预演共用只读脚本、事件、节点与任务索引，每局分别持有游标、任务进度和回滚状态。保留完整剧情索引，确保跨脚本调用和旧档在退出原局前完成校验。用同一实验复测之前测到的约 16 MiB 额外开销。

- 退标题时停止自动保存、取消旧请求，等世界和舞台退出后解除会话、导演、检查点、面板订阅和最后一张地图的角色引用。退出回调只清理对应旧局。读档失败或取消后，原局继续可用。

- 地图解析结果保留最近 2 张已完成地图，正在使用的地图及共用中的下载继续有效。动作姿势由本局换装池持有，合成期间固定所需姿势，退标题时释放。开发版和调试模式继续完成全量校验，随后释放校验临时数据。

- 首屏保留操作栏和共用图标图集，菜单按实际使用加载图片。对白保留当前和下一段已准备的立绘。按状态栏和小地图迁移后的实际使用情况，清理控制皮肤、状态栏和小地图的重复图片，并分别验证网页界面和游戏画布首屏。商店装备首次打开时读取，品级数据复用已有角色数值表。

- 常驻基础界面音和通用战斗反馈，按当前武器、已学技能、伙伴、敌人和剧情准备特殊音效，正在播放的声音播完再释放。游戏内保留当前及上一首背景音乐，回标题释放上一局音乐历史。

- 成功放逐佣兵时删除其掉落保底计数，转入预备队时保留。读已有存档后按恢复的名册清理已放逐佣兵的历史记录，下次正常保存写回。覆盖 20 人招募放逐、保存重读和放逐失败。

## 本机调试标记

使用 IndexedDB，也就是浏览器与 Android 内置网页支持的本机数据库。每个标记分别保存摘要和完整现场；列表按页读取名称、时间、职业和地图，恢复时才读取对应正文。手动命名和自动命名的标记保留到主动删除或覆盖。

保留「记标记」「回到最近」，增加历史标记的选择、恢复和删除。写入完成才提示成功；覆盖失败或设备空间不足时保留原标记。控制台的 `gm.mark()` 和 `gm.recall()` 改为等待完成的操作，面板、文档和调用方同步更新。

恢复标记时进入独立调试现场。先保存进入前的正式进度，再校验并恢复标记中的角色、地图、位置、战斗和剧情状态。调试期间暂停正式存档写入，退出调试后恢复原位置和进度。跨重启恢复时按角色和装备重建外观；任务调试期间创建的标记同时保留任务返回点。损坏、取消或恢复失败时保住原现场和磁盘标记。

调试标记使用独立本机存储空间，正式手动槽、自动槽和云存档沿用现有流程。退出会话时解除调试面板和现场目录对旧会话的引用。

## 验证与交付

- 技能正确性。固定「主角学守护者 → 同职业佣兵离队 → 主角立即施放」回归用例，要求缺项从 7 变为 0，首帧创建特效。覆盖慢加载、连续换装、伙伴和敌人自动施法、被动追击、飞弹中途换人、循环效果及召唤物退场。用六个职业的真实构建内容核对文件、图集页和动画帧。

- 内存与存档。对照同一内容的启动、连续换图、退标题和开新局，检查旧数据的持有者。复测剧情执行器、地图和姿势缓存；验证旧档、死亡检查点、剧情回滚，以及调试标记跨重启、存储空间不足、恢复失败后返回原局。

- 实际画面。按项目约定运行相关测试、内容校验和真实内容构建。用户在同一设备、同一存档验收首次施法、换人后的持续效果、黑暗空间演出及退标题后的内存。报告分别列出已复现并修复的缺图、自动验证和设备实测结果。
