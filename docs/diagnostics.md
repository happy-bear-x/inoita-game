# 手机报错收集

刷新游戏入口（`https://catgo.online:4002/`）后，收集器会自动运行。手机不需要打开控制台或游戏菜单。复现卡住后保持页面在前台至少 8 秒，再告知排查者发生时间。

`public/diagnostics.js` 在游戏模块之前执行，记录 `console.error`、全局异常、未处理的 Promise 拒绝、页面资源错误和 WebGL 上下文丢失。图片与内容加载入口另记录已经被游戏捕获的加载错误。记录包含时间、设备浏览器、地图、主角位置与血量、当前攻击目标、操作锁、剧情节点、最后一帧阶段，以及 WebGL 上下文丢失和恢复。既有控制台输出和异常处理继续生效。

帧阶段使用 Phaser 的 `PRE_STEP`、`POST_STEP`、`POST_RENDER` 事件观察。页面在前台超过 5 秒没有下一帧时，独立计时器会产生 `frame-stalled` 记录。后台与恢复前台的等待不计入超时。这只证明没有出帧，不能直接证明根因；暂停或图形上下文丢失也可能产生该记录。

4003 开发页每次点击跳过后写一条 `story-skip-summary`。`logicMs` 表示剧情逻辑推进到结束或必须停下的确认所用的毫秒数，`worldReadyMs` 表示相应画面或正式世界就绪的耗时，`unlockedMs` 表示归还操作权的耗时；都从点击时刻开始计算。`outcome` 为 `released`、`choice`、`quest-popup` 或 `cancelled`，分别表示交还操作权、停在选择、停在任务确认、取消播放。选择或确认期间的人工等待不计入跳过耗时，尚未经过的阶段为 `null`。摘要共用现有日志的游玩编号和时间，只带计时数据。对照同一存档的开场、同图和跨图剧情；已合成的人物外观应在换图和舞台之间复用。

4003 开发服务自动采集掉帧。刷新页面正常跑图或战斗，出现卡顿后继续玩 10 秒。每满 5 秒的前台游戏帧写一条 `frame-sample`，同一会话可按 `session` 和 `time` 找回。切到后台、竖屏挂起或引擎暂停会清空未完成的窗口。

`details` 记录实际窗口时长、帧数、平均帧率和超过 33/50 毫秒的帧数。`slowest` 记录该窗口最慢一帧的地图、已加载的佣兵数与敌人数（不含友方召唤物）。`frameMs` 从上一帧完成绘制算到本帧完成绘制，分为帧间等待 `waitMs`、游戏更新 `updateMs`、主线程提交绘制 `renderSubmitMs`。显卡实际完成绘制的时间需另行测量。更新中的 `combatMs` 含队伍规划和跟随路线的 `partyPathMs`，`worldTextMs` 累计任务标记和拾取文字定位。摘要单独上报，完整世界快照只在原有诊断事件中读取。

## 低配手机的网页内存记录

手机连开发电脑所在网络，横屏打开电脑的局域网地址和 4003 端口。刷新一次即可开始采集，普通游戏入口就能用。卡顿后继续玩约 10 秒，记下时间、地图和操作。两项排查共用同一次游玩的 `session`、时间和上报接口。

- **启动设备记录** `memory-device` 带标题页版本、画布实际像素、目标帧率和浏览器提供的设备内存档位。浏览器和屏幕像素比来自同条日志的 `userAgent`、`viewport`。手机浏览器缺少某项接口时值为 `null`。
- **持续占用** 在每条 `frame-sample.details.memory` 里。贴图按引擎实际登记的纹理键计一次，每个源图按宽 × 高 × 4 字节估算，共用图集只计整页一次。Phaser 文字和遮罩在改尺寸或直接销毁贴图时也同步更新。音频按实际解码的声道数 × 每声道采样点数 × 4 字节估算；`unknownAudio` 是无法估算的缓存条数。两者都是资源估算，脚本堆读数单列为 `heapBytes`。回前台或从竖屏恢复后，首条完整摘要的 `firstAfterResume` 为真。
- **缓存与对象** 包括已解析地图、人物动作和进行中的内容请求，另记引擎中排队、下载与处理中的文件数。世界侧记录保留的角色、召唤物、当前会话与检查点；特效数指共用渲染器创建且尚未销毁的特效容器。支持弱引用的浏览器另报最近八次安装的会话中仍能读到的数量，垃圾回收发生的时间会影响该值。界面侧统计文字层下的标签、键盘处理器，以及游戏、缩放、场景和场景输入发射器上登记的监听数。
- **切换峰值** 用 `memory-step`。同一操作的开始和结束共用 `id`（位于 `details` 内）。进图、剧情预加载、剧情换幕、读档和回标题分别记录开始、完成、出错或取消。完成记录的 `peak` 是贴图加已知解码音频合计最高的那个时刻，两个分量取自同一时刻。`largest` 列出当时最大的五张贴图，`largestAdded` 只列本次加载的前五张。条目带持有者名称；没有登记持有者时是空列表。
- **清场与关闭** 用 `memory-cleanup` 比较世界战斗销毁、场上最后一个敌人实例移除、剧情舞台释放和游戏面板关闭的前后值。关闭面板可能仍保留隐藏的文字，结合重复操作后是否继续增长来判断。

按手机提供的时间找到 `memory-device` 或 `frame-sample`，再按同一 `session` 查后续日志。对照同一台手机、同一存档在预热后的切图与回标题记录，同时查看超过 50 毫秒的帧数。开发页在首次准备内容时还会读取剧情引用的地图和衣柜动作做校验，应将这次读数与后续重复游玩分别比较。

复测时使用同一台手机和同一份测试存档，中途保持页面打开。先读档并回标题五次，再在相邻两张图之间往返十次，然后经过至少六张不同地图。战斗中重复召唤和清场，开关背包与队伍预览十次；跨图剧情各试一次正常结束和跳过。最后触发自动存档、读档、重试检查点，并切后台再回来。

## 上报与查询

4002 的 HTTPS 入口（nginx 转发到 4004 静态服务）与 4003 开发服务都挂载 `POST /__diagnostics/report`，收到后追加到 `.diagnostics/client-errors.jsonl`，每行一条 JSON。文件达到 2 MiB 时轮转：当前文件 → `client-errors.previous.jsonl` → `client-errors.previous-1..6.jsonl`，共保留 7 份（约 14 MiB），全部被 Git 忽略。旧客户端每帧重复上报的同一条检查点诊断，同一会话在同一张地图 60 秒内只保留第一条，避免把有用的记录挤出保留窗口。服务器在写入成功后才确认，发送失败保留手机上的待发缓存并定时重试；刷新页面也会重发。传输重试可能出现相同 `id` 的记录，排查时按 `id` 去重。

在项目根目录查看最新记录：

```bash
tail -n 30 .diagnostics/client-errors.jsonl
```

浏览器内可用 `storyDiagnostics.export()` 导出最近 32 条内存记录及待发记录。待发记录使用单独的 `inotia4.diagnostics.pending.v1` 缓存键，与游戏存档无关。只在页面启动、出错、停帧和少量关键流程节点（如跨图舞台预取、重建、落位失败）记录，不逐帧上传。客户端限制数量、对象深度与长度；服务器限制请求大小并轮转文件。

独立静态构建包含客户端收集器；只要 4004 的 `tools/serve-built.ts` 和 4002 的 nginx 在运行，上报端点就可用。若用其它静态服务器且没有接收接口，则只保留本地待发记录。JavaScript 死循环、浏览器进程崩溃或系统强制结束页面，可能让收集器也无法执行；没有收到报错不代表游戏没有异常。
