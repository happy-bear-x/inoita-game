# GM（调试）模式

默认关闭的开发工具：完成任务、穿墙、改角色状态，并把当前状态直接上报到服务器——手机上没有控制台也能交出可查的现场。手机报错收集见[诊断说明](diagnostics.md)。

## 一份实现，两条通道

```
src/debug/gm-actions.ts      唯一实现（只依赖纯逻辑模块，不引入 Phaser/UI）
  ├── src/ui/phaser/gm-panel.ts  人：游戏内「系统 → 调试」面板（触摸）
  └── globalThis.gm          agent：浏览器里经 CDP 驱动
```

两条通道调的是同一份代码，所以「agent 验过的」与「人点的」是同一件事。**`gm-actions.ts` 不得引入 Phaser 或 UI 模块**——测试直接 import 它，引入后无引擎的单元测试就断了（`tests/gm-actions.test.ts`）。

## 打开与关闭

| 方式 | 作用范围 | 用途 |
|---|---|---|
| 点击标题页右下角的版本号 | 写进本地存储，刷新后仍是开 | 手机（没有键盘） |
| 地址加 `?gm` | **仅本次会话**，不写存储 | 桌面、agent、自动化 |

打开后标题页角落常驻一行「调试：开」；关闭时这行不存在、系统页也没有「调试」入口——**开关关闭时不装配动作层**，`globalThis.gm` 与 `app.gm` 都不存在，所以「默认关闭」是结构上的保证，不靠调用方自觉。

## 面板与浏览器通道

**游戏内面板**：点击版本号打开开关 → 进游戏 → 「系统」页多出「调试」。面板里的结果就地显示，不弹结果框。

面板现有四个子页：

- **状态**：地图与坐标、任务与剧情计数、最近操作；[上报当前状态]、[脱困]；另有[完成任务]、[穿墙]、[2 倍速度]。有等待中的剧情战斗时，[完成任务]会先按打赢结算战斗，再由剧情事件结算战斗并接取后续任务；当前显示的任务与战斗无关时，优先处理战斗，不直接完成该无关任务。
- **人物**：选择主角或上阵伙伴，查看等级／经验／HP／MP；[升一级]（只升不降）、[回满 HP]、[回满 MP]、[全队回满]；对选中角色切换[无敌]与[技能无 CD]。倒下的角色点[回满 HP]会走战斗侧复活。
- **道具**：按分类（全部／装备／消耗／材料／任务）浏览可发放物品；装备按短剑、长剑、布甲等种类连续分组，同组内等级从低到高。整页用滚轮或拖动滚动；点击物品格会弹出与背包一致的详情层，点右上角关闭。选中一件后用 `-10/-1/+1/+10/+100` 调整数量，[加入背包] 发放；底部可加金币（+1万／+10万／+100万）。列表排除只能地面拾取的物品。
- **任务**：左侧显示全部 231 个任务组，按 `campaign.quests` 的故事顺序排列；主线组和支线组混排，不再单独分栏。支线组在下方的详情里显示「解锁于」的主线组。左侧框上方、与页签同一行是搜索框，输入任务名或任务组名后跨全部任务显示结果；点结果打开对应任务详情。右侧先列出所选任务组的全部任务和状态，选中任务后显示详情：[跳到可接取]、[跳到进行中]、[跳到待交付]。点击后先打开存档页，把当前进度存到任意手动槽才开始跳转；离开存档页或关菜单就取消。跳转会补同组前置和接取剧情自身缺少的任务/选择/事件条件，传送到起点并自动播放接取剧情；接取剧情播完后清掉跳转用的强制状态、刷新回滚检查点并补一次自动存档，之后按正式游戏继续。想回到跳转前，读取刚才存的档。

`completion: 'talk'` 的零目标任务没有进行中阶段，起点是待交付：规划会把模式归一成 `ready`，传送到 `places.ready`，并补齐交付 NPC 的 placement 条件（例如卓拉德在影营地需要 `quest-npc-located-npc-40`）。应用计划时先放成可接取，再走真实的 `quest accept` 命令，让任务簿决定 ready/active。

接取剧情播放前，跳转会扫描接取脚本自己的舞台声明，按舞台地图补齐 cast 依赖的世界实体：先按 `worldEntityId`（没有时按 `characterId`/`actor`）找到 `campaign.placements`，再到剧本里找建立它的 `world place` 节点，重放该节点的 `world` + `flag` 命令。世界登记在别的地图或已移除时同样重放；条件要求目标任务已完成的事件属于未来，不会被当成来源。上游演出不播，任务、物品和队伍命令也不重放。像 quest-10 的莱曼需要 `event-10` 的摆放；quest-153 的舞台在 leap-gate-district、任务目的地却在 kamuran-wilderness，所以不能只补目的地。只有 `flag`/`always` 类摆放找不到来源时才会在跳转结果的警告里点名演员。

剧情跳转不维护自动事件白名单：设置阶段临时挡住自动派发，接取剧情同步启动后清除，之后自动派发完全按正式的任务、区域和近身条件执行。因此正式游戏里的后续任务链在跳转后同样成立（例如 quest-10 → quest-11 → event-15 → quest-12）；跳转补出的前置状态也可能让其他正式自动事件参与派发，这是有意保留的复杂度。所有 `source: 'start'` 事件在跳转时记为已完成，换图不会重播开场。起点还会补齐目标/条件任务的交付物品；接取剧情播完后会清掉强制状态、刷新回滚检查点并补一次自动存档。

剧情跳转只用于把进度定位到任务起点：`forcedAvailable`、钉住前置进度的 `forcedProgress`、接取条件补丁、设置阶段的临时过滤器和跳转前的内存快照只活在跳转过程中，不进入正式存档；跳转产生的任务状态、物品和位置会作为真实进度保留。

**agent，有浏览器**（只在必须看画面时）：开 `?gm`，然后

```js
gm.digest()        // 与面板、上报同一份摘要
await gm.report()  // 摘要 + 最近操作上报到诊断端点
render_game_to_text()   // GM 打开时返回的就是 digest()，含实时玩家坐标
```

## 状态上报

面板的「状态」页与 `gm.report()` 会把**摘要 + 最近 40 条 GM 操作**发给既有的报错收集端点（`/__diagnostics/report`，见 `tools/diagnostic-collector.mjs`）。`gm-state` 属于运行记录，落到 `.diagnostics/client-session.jsonl`；错误、警告、恢复和加载失败进 `client-errors.jsonl`。排查时用 `npm run diag:session -- <会话 id>` 看完整时间线，没有会话 id 的 GM 记录在「(无会话)」分组里。

端点单条上限 12 KB，所以摘要是**摘要**：超出时逐级丢掉最占体积的列表（操作日志→世界实体→世界标记与选择→任务列表→已完成事件）并在返回值里说明已裁剪。`.diagnostics/` 由 4004 打包静态服务与 4003 开发服务共同写入；手机验收走 4002 的 HTTPS 入口，由 nginx 转发到 4004。

## 调试开关的生命周期

`无敌`、`技能无 CD`、`穿墙` 和 `2 倍速度` 是**运行时调试开关**，不进入 `SessionState`／`WorldCombatState`／`CombatCooldownState`：

- 不写存档；
- 同一次页面会话内跨地图保留（无敌、无 CD 存在 `Session` 上；穿墙和倍速存在 `app` 上，换图重建 `WorldCombat` 都不会丢）；
- 刷新页面或新建会话后消失。

## 已知限制

- 无敌拦战斗 HP 伤害（`CombatConditions.canLoseHealth` 门）与 MP 扣除（`losesMana` 门）：技能费用和吸蓝都不扣 MP；状态、增益等其它非伤害效果照常结算；剧情命令直接改血、GM 自己的回血仍会生效，不是全局免伤。
- 道具页排除只能地面拾取的物品；这类由动作层过滤。
- 全队回满会尝试复活倒下角色，但复活表现依赖战斗场景；没有战斗场景时只回满存活成员，并在结果里说明。
- 摘要是给人看现场的**摘要**，不是全量存档；要完整状态用存档槽。
- 普通 GM 修改直接落在当前会话，正常保存会写进存档。打开开关会让 GM 代码进入运行时；关闭时不装配动作层。

## 画面恢复（WebGL）

浏览器切到后台、驱动重置或显存被回收时，WebGL 上下文会丢失。Phaser 会重新创建着色器、缓冲区和普通图片纹理；项目额外在 `restorewebgl` 事件里重画两类只有显存副本的内容：

- 衣柜用 `DynamicTexture` 合成的人物外观，按原纹理键重画，角色和动画不需要重建；
- 滚动区的静态遮罩，标记为需要重做一张遮罩纹理。

诊断会记录 `webgl-context-lost` 和 `webgl-context-restored`。如果只看到丢失、没有恢复，通常说明整个页面进程被系统杀掉了，需要重新打开；这时只能靠本地存档恢复进度。
