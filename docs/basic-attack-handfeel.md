# 普攻与走A对比（2026-10-31）

> **处理边界：这份文档只用于对照和决策。**
> 除非用户明确要求优化普攻/走A手感，否则不要主动修改节奏锁、攻击门控或走A相关代码。
> 日常修复不得顺手调整这些行为；需要动之前先回到这份文档确认取舍。

## 结论

站定不动连续普攻的节奏，当前实现和原版基本一致；用户不适应的主要是三件事：

1. 取消后摇不再加速，走A从“能提高输出”变成“纯位移”。
2. 普攻锁不可见：角色站着、按钮亮着，按了没反应。
3. 走A后必须重新按攻击，按早了会被吞掉，没有输入缓冲。

8927a19 的节奏锁堵住了“取消后摇刷攻速”和“切人刷新普攻”两个漏洞，这是对的；但它把原版本来就有的走A收益一起锁掉了。

## 原版机制

### 1. 普攻没有独立冷却，节拍就是动作本身

原版判断能不能再打，只看“当前动作是不是站立”（`CHAR_IsCurrentActionStand`）。普攻伤害在动画的命中帧结算，动作到结束帧才真正结束。攻速只缩短结束帧，不提前命中帧。

六职业默认节奏（逻辑帧 60ms）：

| 职业 | 完整周期 | 命中帧 |
|---|---:|---:|
| 黑暗骑士 | 600ms / 10 帧 | 240ms / 4 帧 |
| 忍者 | 480ms / 8 帧 | 120ms / 2 帧 |
| 黑魔导 | 600ms / 10 帧 | 60ms / 1 帧 |
| 祭司 | 660ms / 11 帧 | 240ms / 4 帧 |
| 暗影猎手 | 720ms / 12 帧 | 600ms / 10 帧 |
| 狂战士 | 720ms / 12 帧 | 240ms / 4 帧 |

### 2. 按一次攻击键，站定就会自动连打

旧笔记写“按住才连打”，这次复核认为不准确。原版在普攻动作里排了“下一动作 = 默认普攻”（`CHAR_SetAction → CHAR_SetNextAction(+0x290) → CHAR_ProcessAI → CHAR_StartActionNext`）。只要目标还在、角色站定，按一次就会一直打；按住只是重复输入，主要用于第一次起手或连打链断掉后重新起手。

### 3. 移动会立刻取消普攻

方向输入一进来，原版直接把当前动作换成走路，同时清掉目标，自动连打链断掉。任意帧都会取消：

- 命中帧之前移动：这一击没有命中。
- 命中帧之后移动：伤害保留，已经发射的投射物继续飞。

松开方向、重新按攻击，就能再打。这就是走A。

### 4. 走A的收益

原版走A的命中间隔约为「命中帧 + 移动/回站立/重新按的攻击输入延迟」。按输入延迟约 3 帧估算（未逐帧实测，只看量级）：

| 职业 | 站定自动连打 | 走A估算 | 走A收益 |
|---|---:|---:|---|
| 黑魔导 | 600ms | 240ms | 快很多 |
| 忍者 | 480ms | 300ms | 快一些 |
| 黑暗骑士 | 600ms | 420ms | 快一些 |
| 祭司 | 660ms | 420ms | 快一些 |
| 狂战士 | 720ms | 420ms | 快一些 |
| 暗影猎手 | 720ms | 780ms | 反而更慢 |

原版走A有收益、有上限：命中帧越早、后摇越长，收益越大；攻速越高，后摇越短，走A收益越小。限制来自动作帧和输入操作，不是攻击冷却。

### 5. 技能与切人

- 技能可以随时取消普攻后摇，不需要站着；技能期间不能移动。
- 切人不取消动作：旧角色继续把动作打完（转 AI），新角色如果正在走路会被改成站立。
- 画面在素材播完时先切回待机，逻辑动作可能还在后摇；原版也有“看起来站着、其实不能打”的窗口。

## 当前实现

### 1. 节奏锁

8927a19 给每个角色加了独立的 `basicReadyAt`：

- 从动作真正开始播放的逻辑帧起算，封到“开始帧 + 完整周期”。
- 攻速只改变周期长度；动作存活期间每个逻辑帧重算结束帧。
- `cancel()` 只停动作，不归还出手资格；只有 `reset()` / `restoreState()` 清锁。
- 玩家、队友 AI、敌人、召唤物都走同一套锁。

### 2. 移动与走A

- 前摇（最后一次命中之前）不能移动，这是更早的 4b6dd64 引入的，不是 8927a19。
- 后摇可以移动，但下一击仍要等完整周期。
- 移动会清目标、解除自动连打；停下后必须重新按攻击。
- 按在锁内会被直接丢弃，没有输入缓冲。

以黑魔导法杖为例：出手帧 1，旧版取消后约 60ms 能再打，现在要等 600ms，差约 10 倍。

### 3. 切人、自动连打、反馈

- 切人不再取消动作，各角色保留自己的锁；切到刚出过手的队友，可能立刻按不出普攻。
- 站定自动连打会每帧重试，能顺滑穿过锁；走A之后没有这个重试。
- 锁不可见：角色可能已经待机，攻击按钮仍然亮着。
- 视觉待机早于锁结束：画面已经收刀，逻辑上还在后摇。

## 差距表

| 场景 | 原版 | 当前 | 手感影响 |
|---|---|---|---|
| 站定连续普攻 | 周期 = 动作结束帧 | 周期 = 完整周期 | 基本一致 |
| 命中后移动取消，再打 | 约命中帧 + 输入延迟 | 等完整周期 | 差异最大，走A失效 |
| 命中前移动 | 立即取消攻击，可能丢这一击 | 前摇不能移动 | 当前更保护前摇 |
| 技能取消后摇 | 可以 | 可以 | 一致 |
| 切人 | 不取消动作 | 不取消动作 | 一致，且修掉了旧版切人刷新 |
| 画面待机 vs 可出手 | 素材播完先待机，后摇还在 | 取消后立即待机，锁还在 | 当前“假待机”窗口更长 |
| 按早了 | 攻击键只在站立时接受，也会吞 | 锁内直接丢弃，无反馈 | 当前按钮一直亮，更容易觉得吞键 |

## 为什么用户会不适应

1. 走A从“能加速”变成“纯位移”。
2. 锁看不见：角色站着，按钮亮着，按了没反应。
3. 按早了没有补偿：按在锁内就被吞掉。
4. 视觉待机早于锁结束，加深“为什么不能打”的困惑。
5. 切人后新角色可能还在锁里。

## 平衡选项（供后续决策，不自动实施）

### A. 先把反馈补上（成本最低，不改变数值）

让普攻锁可见：按钮灰化/画冷却扇形，或者在锁结束前几帧允许输入缓冲（按早了记到锁结束自动出手）。不恢复走A，但解决“按了没反应”。

### B. 让锁跟随视觉待机（折中）

锁结束时间从“完整周期”提前到“素材播完、画面回待机”的帧。走A恢复一部分收益，幅度比旧版小。需要确认不会重新打开“取消后摇无限刷”的口子。

### C. 给移动取消单独开一条短间隔（最接近原版）

原地取消仍等完整周期；“移动取消后重新站定”允许在「命中帧 + 固定输入延迟」后出手，同时设全局最小攻击间隔。保留原版走A手感，又不至于像旧版那样几乎无成本刷攻速。

### D. 完全回到动作门控（最像原版，风险最高）

取消动作即结束锁，恢复走A；必须额外加“最小攻击间隔”防止重新出现无限加速。切人不取消动作可以保留。

建议顺序：先做 A，观察反馈；如果用户仍觉得走A被砍太多，再做 C 或 B。不建议直接回到 D。

## 证据与未闭合

原版证据来自 `libgame.so` 只读反汇编和现有 findings：

- 攻击门控：`GAMESTATE_PressKeyPlay` 的 `CHAR_IsCurrentActionStand` 分支。
- 自动连打：`CHAR_SetAction → CHAR_SetNextAction(+0x290) → CHAR_ProcessAI → CHAR_StartActionNext`。
- 移动取消：方向输入分支 `CHAR_StartActionID(2)` + `CHAR_SetTarget(0)`。
- 技能接管：`CHAR_ProcessShortcut` 在站立门控之前处理。
- 切人：`PLAYER_SetActivePlayer` 只交换控制权，不取消非走路动作。

未闭合：

- 走A的实际输入延迟、触屏按下/抬起是否落在相邻逻辑帧，没有逐帧实测；报告里的走A间隔是量级估算。
- 旧笔记“按住才连打”需要修正为“下一动作队列自动连打”；当前实现的站定自动连打方向和原版一致。
- 本次没有运行原 APK 做动态逐帧对拍。
